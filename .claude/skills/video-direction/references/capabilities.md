# 能力邊界：哪些用程式做、哪些用素材、哪些外包

**用在**：第 3 步寫概念與腳本、第 5 步排分鏡時，每一拍先決定「誰來做出這個畫面」。品質的上限在這一步就決定了一半：用程式硬做它不擅長的東西，修再多輪也到不了參考的水準。研究出處見 `docs/research/claude-video-limits.md`。

## 一、三個天生的限制

1. **看得懂靜圖，看不懂動態**：構圖、字、版面從截圖判斷得不錯；速度、節奏、順不順從抽格判斷不出來（2026 年的影片理解研究：抽更多格也補不起來）。所以動態交給量測（review-pack）和使用者的眼睛，不靠自己看片判斷「有沒有質感」。
2. **程式做動態有擅長和不擅長的**：見下表。
3. **品味來自餵進去的素材**：沒有參考、品牌規範、真實產品畫面與設計好的元件，出來的就是通用的預設長相。

## 二、每一拍的做法

| 畫面 | 誰來做 | 說明 |
|---|---|---|
| 文字動畫、大字排版、字的進場 | **程式** | 最擅長；時間精準、可對拍、好改 |
| 產品介面示範、游標、點擊、表單、對話 | **程式＋真實截圖** | 介面用真的產品畫面或照真的重建（標「情境示意」），動作用程式 |
| 數據、圖表、計數、流程圖、地圖 | **程式** | 擅長；數字從資料來 |
| 版面切換、卡片、遮罩、條狀掃過、硬切、甩鏡 | **程式（先找登錄庫）** | 擅長；先用 HyperFrames 登錄庫與自己的範例 |
| 同時很多元素在動的複雜畫面 | **拆開** | 程式做時版面容易亂；拆成兩拍或減少元素 |
| 插畫、手繪感、角色、吉祥物 | **素材** | 設計師的插圖、Lottie、SVG；程式只負責擺位和時間 |
| 有機變形、流體、粒子為主角 | **素材或外包** | 程式做得出來但很難到參考水準；只當點綴 |
| 寫實 3D、產品模型、材質特寫 | **外包** | Blender 烘焙（[3d-bake.md](3d-bake.md)）或 After Effects（`scripts/ae-export.mjs` 雙向）；即時 three.js 不當主角 |
| 寫實人物、場景、b-roll | **外包** | 影片生成模型或實拍（`docs/research/video-gen-models.md`），先過 [assets.md](assets.md) 的授權規則 |
| Logo 揭示、開場的品牌時刻 | **素材優先** | 品牌原本有的動態 Logo 或設計師做的；沒有才用程式，並開 campaign 比 2–3 種 |

寫進 `STORYBOARD.md` 每一景的 `made_by: code | asset | outsource`。`asset` 和 `outsource` 的拍要在第 2 步的素材盤點裡列出缺什麼、誰提供；缺了就改寫這一拍，不要硬用程式補。

## 三、概念朝擅長的方向寫

同一個意思通常有程式做得好的演法。「簽約完成」用一份文件上的簽名筆跡、印章落下、狀態從「待簽」變「已生效」，會比 3D 紙張摺疊更容易做到頂。第 3 步提主線時，每條主線的主角時刻都要能歸到上表的「程式」或已經有的素材；需要外包的主角時刻要先問使用者有沒有預算與時間。

## 四、做不到時換做法，不是一直修

Claude 會把一個已經可以的版本越修越糟。一個問題修兩輪還不行，就停下來二選一：開一個 campaign（`scripts/campaign.mjs`）同時做 2–3 種不同的做法讓使用者挑，或把這一拍改成素材或外包。
