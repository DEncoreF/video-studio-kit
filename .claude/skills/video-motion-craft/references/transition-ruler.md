# 轉場尺：長度、緩動、流暢度

**用在**：做或改草稿的變形、轉場、鏡頭運動與介面元件時，決定幾格、什麼曲線、怎麼不頓不震。手法本身（哪個接縫用哪一招、靠什麼帶過去）在規劃時由 video-direction 的 `references/transitions.md` 決定；這裡只管怎麼做到那個數字。GSAP 等 runtime 的 seek-safe 寫法查 hyperframes 的 `references/runtimes.md`、GSAP 本身的 API 查 gsap-core／gsap-timeline，數字以這裡為準。

**目錄**：§1 實測數字（表與 `ruler-ease.js`）· §2 流暢度（60 fps、不頓、停留乾淨不晃、速度對比與圓肩）· §3 最常用的三招 · 出處

## 1. 實測數字（2026-10-24）

**怎麼量的**：
- 8 支 Prompt Motion 與使用者收藏的作品，都用 /watch 看過，60 fps 逐格量（位置、面積逐格算，節拍用音訊起音）。
- 作品：
  - twoclipping「Shape morphing through UI states」「Photo print app launch film」「UGC ad generator promo」
  - demonugc「Morphing UI states loop」
  - stephanlivera、ajith_io、sudo_kiran 的動態展示片
  - notdwd「Frame by Frame」重製對照

下表格數是 60 fps，30 fps 的片子減半。

| 項目 | 實測 |
|---|---|
| 介面元件的彈簧 | 90% 在 10–14 格（0.17–0.23 秒），停穩在 13–20 格；長距離（約 200 px 以上）90% 在 17 格、停穩在 26–28 格 |
| 彈簧曲線（兩位作者幾乎一樣） | 第 1–14 格約 7, 14, 23, 32, 40, 49, 57, 64, 71, 77, 82, 86, 89, 91%，16 格 95%、18 格 97%、20 格 100%：強烈減速，頭 1–2 格稍慢 |
| 抽象形狀變形 | 8–12 格；爆開、穿過畫面 1–8 格 |
| 收縮與離場 | 先加速再減速（S 曲線）11–17 格；縮成一點用加速 |
| 填滿畫面 | 加速 8–11 格（每 2 格約 ×1.5–2.7）；印相片的淹沒例外，是減速 |
| 蓄力 | 點擊驅動的動作：0（游標點下去就是蓄力）；跟節拍的變形：放大 5% 一格；換場：先縮到 3–5% 停 4–5 格再爆開 |
| 過頭 | 多數 0–1.5%；全片一個「彈出」約 6%；抽象形狀、圓點 10–16%；只過頭一次，偶爾回縮 −2% |
| 停穩 | 10–22 格；一次完整變形（起動到靜止）約 25–30 格 |
| 擠壓伸展 | 移動中的膠囊拉長 30%（前緣領先 4–5 格）；一軸壓扁時另一軸變寬 9%；撞擊壓扁到高寬比約 0.56、持續 4 格 |
| 容器裡的內容 | 舊內容在形狀起動時 4–6 格內模糊淡出；形狀到約 80% 時新內容模糊淡入，每列錯開約 5 格。**只用在同一個容器裡的小內容**（同一張卡片換字）；拍與拍的交棒不能用，用了就是溶接（SKILL.md 第 4 步；E 片 draft 28 的 S5、S7） |
| 變形後停留 | 過場狀態 6–10 格；要讓人看到的狀態 16–20 格；要讀的狀態 0.5–2.2 秒；片尾 1.0–1.3 秒 |
| 節拍 | 變形在拍點 ±3 格內起動，或在拍點落定（提前半拍起動，拍點前已到 95%）；換場放在小節線上（`library/motion/beat.js`、`scripts/measure/beat-check.mjs`，[reads-and-beat.md](reads-and-beat.md) §9） |
| 切點 | 4 支中 3 支看得見的切點是 0：換場藏在 7–16 格的純色畫面或光圈裡；另一支 5 刀都切在動作中 |
| 動態模糊 | 每個大動作都有 |

**程式**：`<tool>/library/motion/ruler-ease.js`（`RulerEase.spring`、`pop`、`sCurve`、`accel` 與時長 `RulerEase.T`），把它複製進片子的 `assets/js`。這套數字用在介面元件與主角的變形，**優先於** hyperframes `motion.md` 的「快的動作 0.3–0.6 秒」與「進場太快像故障」：那兩句說的是整個畫面的鏡頭與大字進場。F 片 草稿 4 的變形用 0.6–0.8 秒的對稱緩動，比尺慢約三倍，這是「節奏偏慢」的原因之一。變形要快，停留照 hold 的規則給足。

**緩動性格**（程式裡寫成 `RulerEase.bez(…)`，GSAP 讀不懂 cubic-bezier 字串）：一支片約 3 種，各取名字、寫成 cubic-bezier 或彈簧阻尼比，放在 frame.md 的 `## Motion` 和片子的參數檔（SKILL.md 第 3 步）。常用的起點（Florence、Cinetic）：`out (.16,1,.3,1)` 給進場與字、logo 的揭示；離場加速、比進場短 40–50%；`cam (.48,.1,0,.9)` 給鏡頭；彈簧阻尼比 0.7–0.85 是「高級」，1 不彈，0.4–0.6 俏皮。位置與大小可以彈，透明度與顏色不彈。最慢的動作至少是最快的 3 倍；介面元件的彈簧仍以上表的實測格數為準。

## 2. 流暢度

使用者 2026-10-24 看三段主角變形試片：「呈現沒問題，但是流暢度有待加強」；用 `scripts/measure/motion-profile.py` 量）：
- **60 fps**：尺都是 60 fps。0.1 秒以下的步驟（翻牌一步 90 毫秒）在 30 fps 只有不到 3 格，會一頓一頓的。
- **動作裡不能頓**：一個動作的子步驟（摺第 1、2、3、4 次）互相重疊，下一步在上一步走到約 80% 時就開始，不要等上一步停穩。頓點（動 → 停 ≤ 0.25 秒 → 動）要是 0；主體只停 1–2 格不算頓點，停 ≥ 3 格才算（審片關卡 2026-10-29 起照這個量，規則在 video-draft-review 的 `references/gate.md`）。
- **停留乾淨，不晃**：片中的停留構圖不漂移、不呼吸、鏡頭不晃；要撐住停留，讓有意義的小事件繼續長（計數跳到值、長條長、游標閃）。片尾不能有一整段完全靜止，最後的停留鏡頭單向慢推（[reads-and-beat.md](reads-and-beat.md) §10）。不要做來回的「呼吸」：使用者看 C 的預覽說「畫面一直震動」（2026-10-24）；D 片 draft 5 → 6 量到停留更靜反而更好：接縫快而硬、停留乾淨（SKILL.md 第 4 步）。
- **會讓人覺得在震的東西**：
  - 有圖案的陰影（窗格）在字上滑動；
  - 玻璃後面錯位、移動速度不同的文字複本；
  - 每格換一次的景深或抗鋸齒抖動取樣（每一格要用同一組取樣）。
- **鏡頭是標點**（huashu-art-motion）：看得清就不動；過渡用緩的，快推、砸入只給重音（揭曉、反轉、關鍵數字）；推進去要拉出來，不連三鏡往裡推。整支每鏡同一個動作——一直慢推或每鏡快推一下——都會變成投影片或太躁。
- **鏡頭動的時候是一條連續路徑**：關鍵點之間用一條平滑曲線串起來，速度只在設計好的停留才降到 0；不要每段各自緩入緩出，否則每個關鍵點都會停一下。
- **動作接動作**：上一個動作的收尾帶出下一個動作（例如翻牌落定的那一下，正好推出底線），不要「做完 → 停 → 再開始」。
- **大動作加動態模糊**。
- **速度對比要大，但轉進煞車要圓**：
  - 使用者看 C 草稿 5 說「過場可以再強烈一點」，指的是「放慢跟加速的更強烈」（2026-10-24）；草稿 6 起每個接縫走「慢 → 爆衝 → 慢慢滑停」，6–10 格衝過去。
  - 使用者看草稿 12j 說「轉場的方式感覺好像可以再順一些」（2026-10-26）：對比要留著，但 6–10 格的爆衝太短、轉進煞車是一個尖角。草稿 12k 起的數字（60 fps，film C `assets/js/c5.js` 的 `ramp()`）：
    - 接縫前 0.3–0.5 秒慢到幾乎停住；
    - 起動提早約 0.1 秒，起步 9–10 格（0.15–0.17 秒，sin² 緩入），高速段 12–16 格；
    - 用約 0.03 秒的圓肩轉進煞車（不是直角），煞車的時間常數 0.22–0.30 秒，0.5–0.7 秒滑進位置；
    - 峰值在同一格（拍上），比 6–10 格的版本低約 25–35%（量到鏡頭峰值速度低 21–43%），仍要是周圍的 2 倍以上（`seam-contrast`），配動態模糊。
  - 換亮度的接縫也一樣：整個畫面的光在一格裡變完會像閃一下（草稿 12k 的 S2），分 5–7 格、帶肩。
  - 主角拍與換世界的接縫對比最強。用鏡頭的峰值速度除以平均速度來量。

## 3. 最常用的三招

1. **一個物件、很多狀態**：同一個圓角矩形靠尺寸與圓角在狀態間彈簧，從不切走。twoclipping 整支 14 秒、12 個狀態都是同一個黑色形狀。這是一種方法，不是預設：硬切、掃過一樣可以（SKILL.md 第 4 步）。
2. **部分變成整體**：現在這個狀態裡的一個元素脫出來變成下一個狀態。例如進度條變成滑桿軌道、滑桿把手變成開關的圓鈕、句號變成主角圓點。
3. **動作 → 狀態膠囊 → 純色淹沒 → 收進真實物件**：印相片片的第 1283–1366 格。按下訂購 → 「✓」膠囊 19 格 → 黑色淹沒 11 格 → 全黑 16 格（藏住介面到實拍的切換）→ 黑色收縮成牆上相框的背面 18 格 → 光圈打開看到裝框的照片 12 格。這就是「寄出 → 紙飛機」的現成樣板。
