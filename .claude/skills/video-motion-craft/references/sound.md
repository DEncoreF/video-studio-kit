# 音效：哪個動作要聲音、用哪個、多大聲、落在哪

**用在**：替草稿配音效、照意見改音效（「點擊聲太高頻」「聽不到」「太亂」「不搭」「切得太突然」）。配樂怎麼選、怎麼剪在 `<tool>/docs/PLAYBOOK.md` 第 11 步；閃避、EQ、限幅的寫法查 media-use 的 `references/mixing.md`；標題的語意音效在 semantic-type 的 `references/sound.md`。

**目錄**：§0 這份怎麼用 · §1 逐動作排音效（spotting） · §2 一支片一組聲音 · §2b 豐富度：系統、疊層、蓄力 · §3 長的聲音 · §4 音量 · §5 同步 · §6 素材 · §7 量與審 · §8 踩過的坑 · §9 混音流程

## 0. 這份怎麼用：預設值，不是規格

這裡的數字和做法是**起點**，來自幾支片的量測與使用者的回饋（每條附出處）。每支片的實際做法寫在那支片的
`direction/sound.md`（聲音計畫）：這支片的尺怎麼用聲音、選了哪一組聲音、密度多少、哪幾條跟這裡不一樣和為什麼。
片子的尺跟這裡衝突時，先量尺、照尺做，在聲音計畫裡寫一行理由；使用者的意見又跟兩者衝突時，照使用者。

沒有寫在這裡的情況，照「這個聲音讓觀眾更懂畫面嗎？」判斷：讓動作更有手感、讓重點更清楚的才留，只是填空的拿掉。

## 1. 逐動作排音效（spotting）：先決定每個動作，再談素材和音量

音效出問題，多半是沒有先把全片的動作逐一看過：有的動作沒聲音、有的一個動作疊兩聲、有的聲音不合那個動作。
所以**先列動作、再挑聲音**，順序如下。

1. **匯出動作**：`node <tool>/scripts/timeline-events.mjs <片>`（時間從畫面來，不手打，§5）。
2. **做音效審片頁**：`node <tool>/scripts/sound-sheet.mjs <片> --spec <音效 spec> --video <成片或試片>`。
   每個音效一列，有那一格的畫面、片中那一段的聲音、音效原檔、它屬於哪個動作；另外列出**沒有聲音的動作**
   （畫面上有接觸或狀態改變、附近卻沒有音效的時刻），以及自動找到的疑點（§7）。沒有成片時先用試片。
3. **逐列決定**，每列寫一句理由：有聲音或安靜？是哪一種聲音角色？主角、主要、次要還是質感？
   - **點出重音，不是每個動作都配聲**。有聲音的是接觸與狀態改變：點擊、按下、落定、翻牌、蓋章、闔蓋、硬切、亮起或熄掉的第一格。
   - **安靜的**：鏡頭滑行與推拉、停留、文字或回答出現、持續的漂移與旋轉、跟拍的滑行。參考片這些時刻都把張力交給音樂。
   - **一個動作一個聲音**。同一格（約 120 毫秒內）已經有點擊，不再疊面板或晶片聲；需要重量時，只在主聲音下墊一層低 8–12 dB 的（§6）。
   - **一串同樣的動作**（三份文件展開、四張單據打勾）：同時發生的算一個動作、一聲；看得出先後的，**每一步都要有聲音**，前面幾步低 1–2 dB，
     最後一下最清楚，克制的片只換音量不換音高。之前一支片曾經只給最後一下，使用者：「有一些連續性的音效沒有完全」。
   - **密度看尺**：先量尺每 10 秒有幾個明顯的重音（設計介面片約 4–6 個，§7 的量法），再比自己的片；沒有尺才用這個數。
4. **給使用者看審片頁**，照他勾的改；改完重做一次頁面再給他看。使用者聽得到、Claude 聽不到，審片頁是讓他快速指出哪裡不對的工具，不是 Claude 自己的驗收。
5. 決定寫進片子的音效表 `build/cues.mjs`（時間從 `events.json` 讀，寫法見 §9），聲音計畫記下這一輪的決定。

## 2. 一支片一組聲音

- **定位也要對**：同樣是數位介面，App 教學可以活潑，高階硬體或企業產品片要克制。之前一支片第一套介面聲（泡泡、上升音階、提示音）被說「太可愛」，
  換成按鍵、輕觸、空氣、悶響、快門才對。一串動作照 §1 每一步都有聲音，只換音量。
- **聲音的材質跟著片子的世界**：紙本文件片用紙、印章、信封；數位介面片用介面聲（輕點、彈出、面板、提示）。
  之前一支片第一版直接拿紙本片的紙聲，使用者：「音效部分感覺有些不太搭」。換世界就換一組。
- **同一個角色全片用同一個聲音**，聽起來是同一套介面；重複時每次音高差 ±0.3–1 半音、音量差 ±1.5 dB，或輪流用 2–3 個變體。
- **怎麼挑**：每種角色找 3–5 個候選，做成試聽片（同一段畫面每個候選放一次，墊在片子自己的配樂下、照它在片中的音量），
  左上角標角色和字母，讓使用者每種挑一個。之前一支片就是這樣挑的。
- 角色清單由這支片的動作決定（§1 的審片頁列出來的），不要沿用上一支片的分類。
- **錄音和程式做的各有所長，逐種角色試聽決定**（之前一支片第三輪，A＝earshot 音效庫、B＝真實錄音，使用者：「各有優缺點」）：
  有材質的短聲音（元件冒出、東西移動的滑行、掃描、點聚攏的漩渦）用錄音（B）；要清楚、有節奏的（章節的木頭敲擊、一陣 tick 雨）用程式做的（A）比較乾淨。
  同一個角色裡個別的 cue 也可以留另一邊（之前一支片的表格滑入）。
- **點擊用使用者挑過的那一聲錄音**，不換成音效庫的，也不疊按壓層（之前一支片：「點擊聲好像使用我們原版的好一點」）。

## 2b. 豐富度：系統、疊層、蓄力

只有點擊、落定、主角換場的片子聽起來「不夠豐富」（之前一支片 v5，使用者：「可以再多發揮一點，不夠豐富，有些動作也可以加聲音」）。
v6 依序加了三層，每一層都量過才加下一層：

1. **每種角色疊層**：同一個對齊點，在主聲音下墊一兩層低幾 dB 的，增益照兩個檔最響的 50 ms 算（`levels.json`），和主聲音一起量。
   之前一支片的起點：落定下墊一層柔和撞擊（−6 dB）、換拍的空氣下墊一層氣音與它的尾巴（−6）、打勾上加一層沒有音高的亮 tick（−8，混音偏暗時）、
   主角下墊 sub（−4）和一個短的低 whoosh 當尾巴（−6）、被擋下墊悶響（−8）。點擊不疊（§2）。
2. **沒有聲音的動作，成系統地補**：一種動作一個聲音、全片一樣，耳朵才學得會「這是章節」「零件到位」「東西在移動」。
   之前一支片補了：章節編號一聲木頭敲擊、大標逐字翻出時每個字一聲 split-flap、零件冒出一聲輕觸、東西移動一聲滑行、掃描線一聲掃過、
   知識庫吸收時一聲輕的呼吸、片頭片尾各一聲 sting。多半是質感層：填滿，重音仍由打點帶。
3. **主角前蓄力**：每個主角打點前一個短而暗的 riser，峰值在打點前約 20 ms、比它低 3 dB；全片最大的段落交界改用唯一一次的 reverse swell。
   這和 §3「沒有長 riser」不衝突：它短、暗、壓在主角下面，聽到的是主角變重，不是一個上升音。
- **房間底噪**：操作密的段落墊一條真實房間底噪，在音樂下約 −12 dB，前後 1.5 秒淡入淡出。
- 每加一層就跑 earshot critique／timeline（§7）：之前一支片從 v5 到 v6d 亮度 969 → 1412 Hz，130 個 cue 都在 100 ms 內聽得到。

## 3. 長的聲音：換場、whoosh、上升、提示

- **留完整的餘音**。音效剪在峰值後還沒消失的地方，結尾會像被剪斷（使用者：「你的換場音效都切得太突然」）。
  剪到它自然落到峰值下 40 dB 左右，最後再淡出 0.2–0.5 秒；拿不準就看原檔的波形，不要用固定長度一刀剪。
- **前段的漸強不要壓在別的音效上**。換場聲的峰值放在接縫那一格，漸強就在它前面；漸強期間如果還有落定、點擊，
  先決定哪一個比較重要：拿掉前面那個、把它挪開，或換一個漸強比較短的聲音。不要把漸強直接剪掉，開頭也會變突然。
- 開頭真的要剪，就用 0.3 秒以上的淡入；結尾同理。
- 這類介面設計片沒有長的 riser，也沒有 sub drop。一支片的大撞擊只留給一兩個最大的時刻。

## 4. 音量：音效的峰值高出「當下的音樂底」多少

每個音效都要站在音樂**上面**。量法：音效最響的 50 ms，減掉音樂在它前一秒的 50 ms 中位數（主角換場改比它打開的那一段，因為前一秒是停頓）。
起點照 earshot 的 launch-film 套件（`~/Projects/earshot/earshot/forge/kits/launch.json`，七支專業發表片的中位數）：

| 角色 | 高出音樂底 | 位置 |
|---|---|---|
| 點擊 | +6.5 dB | 比那一格早約 11 ms |
| 落定、輕放 | +8 dB | 接觸那一格，或晚約 30 ms |
| 換拍的空氣聲 | +9 dB | 峰值在動作開始後約 0.2 秒 |
| 主角換場 | +8.5 dB（比它打開的那一段），前面先停一下 | 峰值在那一格 |
| 撞擊、被擋 | +7.5 dB | 那一格 |
| 打勾、快門、開關 | +4 dB | 那一格 |
| 鍵盤 | +6.5 dB，一秒最多約 12 下 | 每個發聲的字 |

**舊的分層錯在次要與質感層放在音樂底下**（−6 到 −3、−10 到 −6 dB）：earshot 聽之前一支片時，那些打勾、換拍、收疊幾乎都聽不到（高出 0–3 dB），
使用者的感覺是「音效沒有很到位」。改成上表之後，同一批聲音高出 +7 到 +12 dB。

- film C 的量測：參考片最強的重音高出 12–17 dB。
- **主角前先停一下（stop-down）**：音樂在打點前 0.3–0.5 秒退 6–12 dB，**在打點那一格回來**；不要在打點之後才退（舊做法），也不要在每個音效下面退。
  earshot 的七支參考片有四支這樣做。
- **母帶**：−15 到 −14 LUFS，限幅器上限 0.77（約 −2.3 dBFS），成品真峰值 ≤ −1.5 dBTP。上限設太低（0.63）會白白壓扁每一下點擊。
- **亮度**：earshot 量參考片的頻譜重心中位數在 1.2–3 kHz。混音太暗（之前一支片 711 Hz）時，母帶前加一點傾斜 EQ（150 Hz 以下 −3 dB、2.5 kHz 以上 +5 dB），
  音樂那軌做一樣的處理再拿來量。
- 音效乾（不加房間殘響），earshot 的 real-sound 做法。聲像見 §5：只有移動的東西跟著走，點擊、落定、主角置中。
- **鼓很滿的曲子有天花板**：在 −14 LUFS／−1 dBTP 下，點擊大約只能高出音樂底 +5 dB，再推只會讓限幅器把整個混音壓下去，聽起來更亂。
  解法依序：操作很密的段落讓音樂整段退 2–3 dB（1 秒的斜坡）；或選曲時就挑那一段比較稀的；最後才接受低一點的數字。
  不要在每下點擊底下讓音樂短退：一連串的短退會讓節奏一頓一頓（之前一支片）。
- 自動校音量時給倍數設上限（例如原音量的 6 倍）：推過頭的聲音只是在驅動限幅器。
- **很短的點擊先收峰值**：0.08 秒的點擊峰值因數約 11 dB，限幅器會壓掉 10 dB 以上，每一下都讓整段混音被壓一下。
  先對樣本做輕微的軟削波，讓峰值因數降到約 6–7 dB（長度、起音不變）；不要用 loudnorm 這類會改長度、時間的處理。
- **限幅器已經壓掉超過約 3 dB 的聲音，就不要再推**：改成讓音樂在它前後退一點（約 4–6 dB，1 秒退下、2 秒回來；回太快會像突然變大聲），
  或那一段整段低一點，把那一步藏在接縫下面。這是起點，鼓很稀的曲子可能不用退。
- 「音效比音樂小一點」是錯的：草稿 10 的 59 個音效中位數比音樂底**低** 15.8 dB，整支只聽得到鼓。

## 5. 同步

- 接觸類（點擊、按下、落定、翻牌、蓋章、闔蓋）：起音落在那一格到晚 1 格。參考片硬切的起音中位數在 −10 到 +68 毫秒；提早超過 45 毫秒觀眾察覺得到。
- 空氣聲（swish、whoosh）例外：峰值提早約 70–120 毫秒，在動作最快的地方之前。
- **只有移動的東西有聲像**：滑行、漩渦、一陣 tick 雨跟著物件從左到右（`pan_from`→`pan_to`，±0.15–0.45）；點擊、落定、打勾、主角都置中。參考片的重音幾乎都在中間。
  §9 的 `moves` 指定哪些角色保留聲像，其他 cue 寫了 pan 也會被拿掉。
- **cue 的時間從畫面的時間軸匯出，不手打**：`<tool>/scripts/timeline-events.mjs`（說明在 video-draft-review 的 `references/gate.md`），畫面改了就重新匯出。手打的同步點外部量到差 8–11 格（Cinetic）。

## 6. 素材

- **先從共用音效庫挑**：`<個人層>/sfx/`（預設 `~/.video-studio/sfx/`），依用途分類，出處與授權在它的 `CREDITS.md`、分類表在 `README.md`。
  複製到片子的 `assets/sfx/`，片子的 `CREDITS.md` 記來源；新下載、確認過授權的素材用完放回庫裡（照分類，`CREDITS.md` 補一行）。
- **只收 CC0 1.0 與 Pixabay Content License**；CC-BY、CC-BY-SA、任何 NC、授權寫不清楚的一律不收。音樂另外要沒有登記 Content ID。
  找的地方：Pixabay 音效、Freesound（看單一檔案頁的授權）、Openverse（授權篩選只勾 CC0）、Kenney（介面音效包，CC0）、Earshot、RealSFX（逐檔確認）。
- **下載**要使用者對下載本身說好（video-direction 的 references/assets.md「原則」）；下載前在來源頁再確認一次授權。
- **真實錄音優先於合成**：程式合成的材質聲聽起來像純音（使用者：不要純音的音效）。`pipelines/music/edit.py` 的合成音色只當草稿佔位。
- 點擊用一聲柔和的真實點擊，不疊大聲的「按壓」層（頻譜重心約 4.7 kHz，刺耳的是它；使用者 2026-10-26：「點擊聲好像太高頻了」）。
- 夜景加一條真實的房間底噪，在音樂下 −30 到 −24 dB。
- **庫裡沒有、程式合成又太像純音的聲音**（tick 雨、漩渦、掃描、滑行），用 `<tool>/pipelines/sfx/resynth.py` 從 CC0 錄音做：每個顆粒都是錄音，
  程式只排位置、密度與濾波，底下墊房間底噪；`--check` 跑 earshot 的檢查與 realness（之前一支片的 take 在 0.67–0.98）。
- **Kenney**（CC0）：kenney.nl 擋 curl，從 GitHub 鏡像拿（Calinou/kenney-ui-audio、Calinou/kenney-interface-sounds、Boyquotes/kenney-impact-sounds-for-godot）。
  收進庫的條件：earshot p_real ≥ 0.75 且諧波比 < 0.1（Interface Sounds 全部聽起來是合成的，一個都沒收）。

## 7. 量與審

- **高出音樂底**＝音效的 10 毫秒 RMS 峰值，減掉前後 1 秒的 10 毫秒 RMS 中位數。分軌量：同一份 spec 另外算出「只有音樂」一軌，逐個 cue 比；母帶的正規化與限幅會改掉 gain，所以不要看 gain 的數字。
- **在成品裡量短的聲音，要先扣掉音樂**：曲子的鼓常落在點擊同一拍，直接讀混音會把鼓當成點擊，自動校音量就會把點擊關到聽不到
  （之前一支片第二首配樂：三下點擊被關到 0.04 倍）。混音減「只有音樂」那軌（限幅器有約 1 ms 的延遲，先對齊）再讀；同時算出限幅器壓掉多少。
- **成品**：整體 LUFS、真峰值、≥ 5 LU 的躍升（審片包 `sound.txt`；數字在 `library/rules/motion.json` 的 `sound`）。
  HyperFrames 算圖會把 `<audio>` 降約 5 dB（之前一支片成片 −18.9 LUFS），所以算完把母帶直接換進 mp4：`ffmpeg -i clip.mp4 -i score.m4a -map 0:v -map 1:a -c copy -shortest`。
- **音效審片頁的疑點**（`sound-sheet.mjs` 會標，只提醒、不擋；門檻在指令列可改）：
  - 同一格兩個聲音：120 毫秒內兩個不是墊層的 cue；
  - 太密：每 10 秒的非質感 cue 比尺多（預設 6 個）；
  - 結尾被剪斷：音效檔最後 50 毫秒還比自己的峰值大 −30 dB 以上；
  - 漸強壓在別人身上：長聲音從開始到峰值之間有別的 cue；
  - 沒有聲音的動作：有接觸或狀態改變（縮放、位移、剪裁的短補間），前後 0.2 秒內沒有 cue。這只是候選，大部分應該照 §1 保持安靜。
- **混音的 spec 產生後檢查一次欄位**：之前一支片當時自己的 `score.mjs` 一行註解吃掉了 `music_env`，主角時刻的「先退再打」從第一版起就沒生效，量音效高度也看不出來（現在由 §9 的 `pipelines/mix/score.mjs` 產生，測試釘住這些欄位）。
- **用 earshot 聽**（`~/Projects/earshot`，MIT；CLAP 與 AST 模型，只用 CPU）：Claude 聽不到聲音，earshot 用聲音模型代聽。
  指令細節在 `/earshot` skill（上游原版，不手改）。**分工**：earshot 只當耳朵——它的 Loop 1–3（挑候選、聽審成片、A/B）與 `measure`；
  用什麼聲音、多大聲、哪裡安靜照這份與那支片的聲音計畫。它的 Loop 4–5（`forge`、`kit`／`sfx` 程式做的音效庫，`ui_pop`、鐘琴等）
  只在聲音計畫明確選了程式合成時用：預設照 §6 真實錄音優先（之前一支片第二套拿掉有音高的聲音，使用者：「有點太可愛了」）。
  `earshot llm` 會上傳音訊給 Google，使用者對上傳說好才跑。指令不在 PATH 上，一律寫完整路徑；每次呼叫先載模型 20–40 秒，要連跑很多次就寫成一支 Python、用 `~/Projects/earshot/.venv/bin/python` 跑（`from earshot import api`）。
  - `~/Projects/earshot/.venv/bin/earshot critique <成片.mp4>`：對七支專業發表片打分，看響度、亮度、頻段、密度、停頓。
  - `earshot timeline <成片.mp4> --cues cues.json`：逐個音效聽出是什麼聲音、高出前一刻多少、有沒有對到畫面；標 NO HIT／CHECK 的要看。
    cues.json 是 `{fps, events: [{f, kind, id}]}`，從音效 spec 轉出來。
  - `earshot match <檔> "描述" --alts "別的描述"`：判斷一個聲音聽起來像不像要的東西（例如換拍聲會不會像呼吸）。
  - 它的分數是參考：作者自己的盲測 15 次猜對 8 次。好不好聽仍要使用者聽。

## 8. 踩過的坑

| 使用者說 | 原因 | 照哪一節 |
|---|---|---|
| 「點擊聲好像太高頻了」 | 疊了刺耳的按壓層 | §6 |
| 「音效部分感覺有些不太搭」 | 沿用上一支片（紙本）的材質 | §2 |
| 「太多地方都太亂了」 | 一個動作兩聲、文字與跟拍也配聲、漸強疊在別的音效上、限幅器被推滿 | §1、§3、§4 |
| 「有些沒有音效，有些不適合」 | 沒有逐動作看過，只照聲音角色套 | §1 |
| 「換場音效都切得太突然」 | 用固定長度剪，峰值後 0.4 秒就斷；又把漸強剪掉 | §3 |
| 「音效沒有很到位」 | 次要與質感層放在音樂底下，換拍、打勾聽不到；主角時刻沒有先停一下；混音太暗 | §4、§7（用 earshot 聽） |
| 「有點太可愛了」 | 會爬音階的打勾、泡泡、閃亮、提示音，聲音太多，配樂偏甜 | §2（材質跟著片子的定位：產品片用硬體與空氣，不用有音高的聲音） |
| 「可以再多發揮一點，不夠豐富」 | 只有打點，沒有疊層、沒有系統、主角前沒有蓄力 | §2b |
| 「點擊聲好像使用我們原版的好一點」 | 點擊換成音效庫的、又疊了按壓層 | §2 |

## 9. 混音流程：`<tool>/pipelines/mix/`

每支片只放自己的資料，程式都在 toolkit（以前每支片各複製一份 `score.sh`／`score.mjs`／`measure.py`，七份都不一樣）：

| 片子裡 | 是什麼 |
|---|---|
| `build/sections.json` | 曲子、BPM、小節對照（`map`）、主角時刻（`heroes`）、`mix`：`lufs`（預設 −14）、`limit`（預設 0.71）、`tilt`、`bedSteps`、`stopDown`、`musicGain`、`heard` |
| `build/cues.mjs` | 音效表：`export default ({ sheet }) => { const S = sheet(import.meta.url, {角色、疊層、swap…}); return S.done([...]) }`，選項寫在 `pipelines/mix/cues.mjs` 開頭 |
| `build/kit.json`、`assets/sfx/kit/` | earshot 音效庫的角色與 take（`earshot kit render`），沒用就不用放 |
| `build/trim.json` | 每個 cue 的音量修正，`measure.py --apply` 寫入 |

```
node <tool>/scripts/timeline-events.mjs videos/<片>                 # 畫面改了先重匯動作
node <tool>/pipelines/mix/master.mjs videos/<片> --trim 3            # 3 輪：分軌 → 量每個 cue 高出音樂底多少 → 修 trim，最後出母帶
node <tool>/pipelines/mix/master.mjs videos/<片>                     # 只出母帶（assets/music/score.m4a）
python3 <tool>/pipelines/mix/measure.py videos/<片> -v               # 逐個 cue 的量測（要先有 --stems 或 --trim 的分軌）
```

出完把母帶換進成片（§7），跑聲音關卡 `node <tool>/scripts/sound-gate.mjs videos/<片> <預覽.mp4>`（earshot critique 與 timeline，判定與豁免在 video-draft-review 的 `references/gate.md` §6）；沒有 SOUND-PASS 的檔，hook 不讓它傳給使用者。新片一律用這裡。
