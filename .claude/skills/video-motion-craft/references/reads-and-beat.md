# 讀點、帶眼睛、節拍：時間怎麼給

**用在**：寫 `direction/script.json` 的 `reads`、`setups`、`seams`（video-direction 第 5 步分鏡、第 7 步轉場會連到這裡），以及做草稿、照意見改草稿時決定每一拍給多久。審片的三種尺度與「看起來像生成的」清單屬於 video-draft-review（`references/review-scales.md`、`references/failure-list.md`），這裡不重述。

背景：使用者 2026-10-25 看過兩份動畫指南（ClaudeAnimationBase 的 ANIMATION_GUIDE，MIT；PDoomVideo 的 ANIMATION_GUIDE，只借想法、不抄程式），同意把 11 條吸收進來：「1–11 都吸收進 toolkit，但要怎麼好好讓他運作要思考一下」。所以每一條都接到工具或關卡上，不只是文件。

借的是想法，不是卡通的畫風：
- 那兩份要「不要字」，行銷片不一樣，要標題和證據的字。這裡把字當成一種讀點，照字的預算算時間。
- 品牌規範優先於這份；和 [transition-ruler.md](transition-ruler.md)、[material-morphs.md](material-morphs.md) 或 video-direction 的 script-craft.md 的實測數字衝突時，以實測數字為準。

## 資料格式（direction/script.json，都是選填，舊的腳本照樣能用）

```json
{
  "total": 61.0,
  "headline_zone": [60, 770, 830, 200],
  "beats": [
    { "id": "02 解析", "t0": 12.1, "t1": 16.3, "…": "原本的欄位",
      "reads": [
        { "t0": 11.92, "t1": 13.4, "what": "整頁被裁成條款", "kind": "motion", "act": 12.83, "size": "big",
          "important": true, "lead": "紫色裁切線從上往下劃，眼睛跟著線走" },
        { "t0": 13.5, "t1": 17.0, "what": "拆成哪六類", "kind": "text", "text": "付款交付驗收保固智財違約其他",
          "size": "small", "important": true, "lead": "鏡頭停在第一欄，每個標籤在拍點變紫", "crop": [0, 120, 1920, 180] }
      ] }
  ],
  "setups": [ { "what": "紙角的紫色摺痕（AI 碰過）", "t": 11.0, "payoff": { "t": 46.0, "what": "摺成紙飛機時摺痕在機頭" } } ],
  "seams": [ { "id": "open", "t": 0, "kind": "open", "device": "夜裡桌燈從暗亮起，鏡頭已經在推", "bar": true },
             { "id": "S1", "t": 4.0, "kind": "seam", "device": "附檔長成整份文件" },
             { "id": "close", "t": 61.0, "kind": "close", "device": "QR 停 1.2 秒，最後一個和弦淡出", "bar": true } ]
}
```

- **讀點**（`reads`）的時間是全片秒數。
  - `t0`：畫面上找得到它的那一刻（出現、開始動）。
  - `t1`：觀眾看懂、記住的那一刻；下一件事更早把眼睛拉走的話，就是那一刻。不是它在畫面上留多久：標題還在、但眼睛已經被下一個動作拉走，讀點就到那裡為止。
- `kind`：`text` 字、`visual` 畫面、`motion` 動作。`size`：`big`（預設）或 `small`。`important`：這一拍要成立、觀眾非懂不可的事。
- `text`：字的讀點用來算字數（沒寫就用 `what`）。`act`：動作在哪一刻落定（預設 `t0 + 0.33` 秒）。`crop`：審片包要用全解析度看的地方（1920×1080 的像素 `[x, y, w, h]`）。`hit: true`：這個讀點的開始是一個打點，要在拍上（beat-check 檢查；重要的動作讀點不用寫，落定那一刻本來就算打點）。
- **標題區**（`headline_zone`，選填）：標題所在的地方，1920×1080 的像素 `[x, y, w, h]`，含副標。重要、不是小字的 `text` 讀點都當標題量（review-pack `head-cross`）；某一句排成兩行、位置不同，就在那個讀點寫自己的 `zone`；不是標題的字寫 `"zone": false`。
- **伏筆**（`setups`）：`payoff` 寫 `{ t, what }`；只寫數字也可以，當成時間。
- **接縫**（`seams`）：
  - `t` 是變化落下的那一格（硬切的那格、爆衝的最高速）；
  - `kind` 是 `open`、`seam`、`close`；
  - `bar: true` 表示這是大變化，要在小節線上；`major: true` 表示主角拍的接縫，要在拍上（不要求小節線）；
  - `device` 寫靠什麼帶過去（video-direction 的 transitions.md 詞彙）。

## 1. 讀點表：讀點決定鏡頭長度

觀眾只看一次、全速、第一次看。每一拍先列出觀眾依序要看懂的事，每一件都要有三段時間：眼睛**找到**它、**看懂**它、**記住**它，下一件才開始。

**最短時間**（script-lint 檢查；重要讀點不夠是 FAIL，其他是 WARN）：

| 種類 | 大 | 小 |
|---|---|---|
| 字 `text` | max(1.2, 字數 ÷ 4.5 + 0.6) 秒（script-craft.md §6 的字的預算） | max(1.2, 字數 ÷ 4.5 + 0.9) 秒：小字多 0.3 秒讓眼睛找 |
| 畫面 `visual` | 0.6 秒 | 1.0 秒 |
| 動作 `motion` | 動作本身可以很快；落定（`act`）之後意思要停 0.5 秒 | 落定之後停 0.8 秒 |

- 小、遠、快、細的東西比大、在中間、明顯的東西更難找、更難懂，所以小的要更久。
- **重要讀點不能重疊**（容許 1 格）。兩件事同時發生，觀眾只會看到一件。最常見的是標題和證據的動作同時開始：標題先讀完、動作再開始，或動作先落定、標題再進來。
- **標題還在，內容就不穿過標題區**：讀點看完不等於標題退場了。接縫的動作（收攏的卡片、拉遠時長出來的表、飛過的軌跡）進到標題區之前，標題要已經退場（淡出中也算還在）；不然就讓內容繞開標題區。film C 深色草稿 6 有三處（S4、S8、S10），草稿 7 把 02、06 的標題提前到接縫之前退場、S10 的軌跡改從左上角來。review-pack 在成片上量（`head-cross`，提醒：刻意讓標題陪著鏡頭穿過去的，回報時說明）。
- **讀點決定長度，不要硬塞，也不要墊時間**：
  - 讀點塞不進這一拍，就加長這一拍，或刪掉一個讀點；不要壓縮讀點的時間。
  - 一拍最後一個讀點看完，到拍尾（拍裡有接縫的話，到那個接縫）還有 1.2 秒以上，就是「停太久」：script-lint 在計畫上提醒（WARN），review-pack 在成片上量「最後讀點 → 成片的下一個變化」，超過就判 FAIL（`hold-long`）。使用者 2026-10-24 看 C 草稿 7 的 04：「停留的有點久」（量到 2.57 秒）。
  - 最後一拍可以多 1.0 秒片尾。
- **最後一個讀點**要在片尾前 1.0 秒以上看完，讓它落地（FAIL）。
- 動作超過 1.0 秒（材質變形超過 2.8 秒）會提醒「動作要快」：要停的是意思，不是動作。

## 2. 重要讀點之前，先把眼睛帶過去

眼睛會去看會動的、亮的、大的、被看著的東西。每個重要讀點寫 `lead`：眼睛怎麼先到那裡。

| 手法 | 怎麼做 | 時間 |
|---|---|---|
| 先動 | 要讀的東西先動一下（彈出、劃線、滑進） | 讀點開始前 0.2–0.4 秒 |
| 先亮 | 紫色亮起、高亮，其他地方變暗或變淡讓位 | 0.2–0.3 秒內到位 |
| 鏡頭過去 | 推近或平移到它，鏡頭先到、讀點才開始 | 鏡頭落定後 ≥ 0.2 秒 |
| 游標 | 人的游標移到按鈕上、按下 | 游標停 ≥ 0.15 秒再按 |
| 大小 | 推近到它成為畫面主體，或字級對比 | — |
| 押韻 | 和上一個讀點同一個位置、同一個形狀出現（配對剪接） | — |

眼睛跳到畫面另一側約要 0.2–0.3 秒；離上一個讀點越遠，要給越多。沒寫 `lead` 的重要讀點，script-lint 會提醒。

## 3. 快的動作、慢的意思

- 動作可以很快，只要有預備（蓄力、游標按下）告訴觀眾要看哪裡：介面的彈簧 10–20 格，變形 8–30 格（[transition-ruler.md](transition-ruler.md) §1）。
- 動作的意思要停：要讀的狀態停 0.5–2.2 秒（轉場尺的「變形後停留」），主角拍更久。
- 不重要的快快帶過，重要的花時間。快和停的對比就是節奏；整支片同一個速度，不管快或慢，都會平、看不懂。
- 量法：motion-profile 的走勢圖要看得到「爆衝」和「停」交替；接縫的峰值速度是平均的 2 倍以上（[transition-ruler.md](transition-ruler.md) §2）。
- 使用者 2026-10-25 看 C 草稿 9 的 02：「你拆解可以快一點，再運鏡從左到右。左到右這部分要讓人大概可以看到拆了哪些」。拆是動作，要快；拆成哪幾類是意思，要停到讀得完。

## 4. 先因、後果

- 原因發生、觀眾看到了，結果才開始。例如按下「寄出」，「✓ 已寄出」就在那一刻出現，紙飛機才開始摺。
- 不要讓結果和原因疊在一起，也不要讓結果比原因早。
- 反應常常是最有趣的部分，給它時間。
- 讀點表裡，原因和結果是兩個讀點，照順序排、不重疊（script-lint 的重疊檢查會抓）。

## 5. 埋了要收

- 畫面裡埋下的東西（紙角的紫色摺痕、一個「?」、一個沒寫期限的條款）要在同一拍或之後收掉。
- 寫進 `setups`：埋在哪、在哪收、怎麼收。
  - 沒有 `payoff` 的伏筆，script-lint 判 FAIL；
  - 收的時間比埋的早、或在片尾之後，也是 FAIL。
- 首尾呼應（script-craft.md §7）是最大的一組：開場的物件或動作，結尾換個樣子回來。

## 6. 我們缺的動畫原則

程式寫出來的動作會像機器：每個部件同時動、同一條曲線、同樣的量。下面幾條補上，數字以轉場尺為準。

- **弧線**：活的東西走弧線，不走直線。紙飛機、被丟出的晶片、游標的長距離移動，路徑都帶一點弧（中段偏移約距離的 5–15%）。
- **重量**：起動和停下的方式說明它多重。
  - 整頁文件、視窗是重的：起動慢一點、過頭 0–1.5%、不彈；
  - 晶片、標籤、膠囊是輕的：一下就動，可以過頭一次（全片一個「彈出」約 6%）。
- **重疊動作與跟隨**：不要所有部件同時動。
  - 容器先動，裡面的內容晚 4–6 格（轉場尺的「容器裡的內容」），最末端的東西最後停；
  - 子步驟在上一步走到約 80% 時就開始（[transition-ruler.md](transition-ruler.md) §2「動作裡不能頓」）。
- **避免雙胞胎**：程式會複製數值，結果一排卡片同時落下、兩邊對稱動。錯開 0.05–0.08 秒、幅度也不要完全一樣；一排裡讓一個領頭、其他跟著。
- **一格一個主角，次要動作要讓位**：每一格只有一個主角在做主要的動作（motionmaxxing、Cinetic）。輔助的小動作（標籤亮一下、陰影跟著動、跟著過來的卡片）增加生命感，但：
  - 走的距離是主角的 50–75%（Florence 寫 50–70%）；
  - 晚出發：主角走到 55–75% 時才起動，或晚 100–200 毫秒（6–12 格），兩者在 2 格內一起停，避免「停頓再猛衝」（Cinetic）；
  - 幅度和對比都小於主角，不在重要讀點開始的那一刻搶戲。
- **關鍵姿勢要強**：每一拍講故事的那幾個姿勢，單看靜圖就要讀得懂：主體清楚、構圖往它正在做的事傾。靜圖讀不懂，動起來也救不了（第 8 條）。
- 已經有的不重述：蓄力、擠壓伸展、緩入緩出、過頭與停穩，見 [transition-ruler.md](transition-ruler.md) 與 video-direction 的 visual-verbs.md「物理感」。

## 8. 先擺關鍵姿勢，靜圖過了才補中間

- 每一拍先做出關鍵狀態（讀點開始、讀點結束的那幾個畫面），用 `node <tool>/scripts/measure/seek.mjs <片> <前綴> <t,t,…>` 截靜圖排成一張，先看這張：構圖、字級、主體清不清楚。
- 靜圖過了，才補中間的動作和轉場。動作沒辦法修好一個讀不懂的姿勢。
- 審片包的 `reads/*-start.jpg`、`*-end.jpg` 就是成片裡的關鍵姿勢：每一張單看都要讀得懂。

## 9. 全片一個脈搏

- 一支片只有一個節拍格線：`build/sections.json` 的 `bpm` 與 `offset`（第一個重拍）。合成裡用 `<tool>/library/motion/beat.js`（`Beat.make(bpm, offset)`，有 `pos`、`n`、`bar`、`pulse`、`snap`、`off`），不要每段各自算。
- **打點在拍上**：接縫、標籤亮起、按下、落定，在拍點 ±3 格（60 fps）內；或照轉場尺提前半拍起動、在拍點落定。開場、結尾與 `major`、`bar` 接縫的動態峰值離拍超過 0.1 秒（6 格），review-pack 判 FAIL（`seam-beat`）；一般接縫只提醒：刻意落在拍外的（跟著動作、不跟著音樂），回報裡說明。
- **大變化在小節線**：換世界、換章節、開場、結尾（`seams` 的 open、close，或寫 `bar: true`）放在小節線 ±3 格內；超過 0.1 秒是 FAIL（`seam-bar`）。開場、結尾、`major`、`bar` 之外的接縫，2026-10-29 起不再因為離拍判 FAIL（規則在 video-draft-review 的 `references/gate.md`）。
- **每個樂句一個畫面**：一個樂句（4 或 8 小節）給一個新的狀態或一拍；不要一個畫面跨過樂句的轉折，也不要一個樂句裡換好幾次。
- 沒有配樂也照樣用一個 BPM（C 用 120 BPM，一小節 2 秒），之後配樂才對得上。
- 檢查：`node <tool>/scripts/measure/beat-check.mjs videos/<slug> --render renders/draft-N.mp4`：
  - 印出每個接縫、每個打點離最近的拍與小節線幾格。打點是重要動作讀點的落定（`act`），或寫了 `"hit": true` 的讀點（標籤亮起、字在拍上出現）的開始；
  - 有成片時，再量：
    - 開場第一格、結尾最後一格是不是已經是完整畫面（硬開、直接停）；
    - 每個接縫實際的動態峰值（`t` 前後 0.4 秒內動得最多的那一格）；
    - 接縫表以外的跳動（觀眾也會把它們當成打點）。

使用者 2026-10-25 看 C 草稿 10：「部分過場在掌握一下節奏」。

## 10. 開場與結尾也是接縫

- 第一格不要是一張硬的畫面：從暗或白淡入 0.3–0.6 秒，或鏡頭已經在動（第一格就有速度）。
- **故事的第一件事要一眼讀得出來**：使用者看 C 草稿 12j：「第一個畫面應該是要說明有信件進來」。開場的夜景很美，但螢幕裡的信太小，看不出發生了什麼。草稿 12k 起：鏡頭推近螢幕，約 2 秒時螢幕佔畫面一半；一張大的郵件卡片在拍上落下（寄件人、主旨、附檔，1080p 上的字 ≥ 32 px），配一聲柔和的通知聲；標題在卡片之後才進來。第一個讀點就是這件事（`kind: "motion"`、`important`），審片時看 `reads/` 的第一張：單看這張讀得出來嗎？
- 最後不要直接停：
  - 最後一個讀點看完，再停 1.0–1.3 秒（轉場尺的片尾）；
  - 停的時候鏡頭仍往同一個方向慢推（每秒約 1–2%）；
  - 最後 0.5–1.0 秒淡出，或用音樂最後一下收掉。
- 接縫表要有 `open` 和 `close` 兩列（script-lint 沒看到會提醒），審片包也會為它們做逐格表；成片的第一格或最後一格還是完整畫面，review-pack 判 FAIL（`hard-open`、`hard-close`）。
- 循環播放的片子，結尾要接得回開場（SKILL.md 第 1 步）：`close` 的最後一格和 `open` 的第一格並排看。
